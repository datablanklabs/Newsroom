# Newsroom

A local search engine, entity index and relationship-network explorer for leaked, declassified
and published document collections: the Snowden archive, WikiLeaks cables, the JFK records, the
Panama Papers, DDoSecrets releases, and whatever comes out next. It grew out of the *Snowden
Archive Explorer*; the Snowden index is still here, rebuilt with the generalized pipeline.

* **`corpora/*.toml`**: one config per dataset: where the files are, what to include, which
  knowledge packs apply, how to read dates and metadata. `corpora/_template.toml` documents every option.
* **`build/`**: `fetch.py` (download a corpus's files from the web), `extract.py` (files → per-page
  text, OCR) and `index.py` (text → SQLite search index, entities, co-occurrence graph, typed
  relations), all run per corpus.
* **`lib/packs/`**: knowledge packs: curated entities, themes, document conventions and header
  parsers for a domain (surveillance, diplomacy, offshore finance, military, Cold War, economics, politics).
* **`app/`**: a Flask web app with a library of corpora, cross-corpus search, entities, network and
  timeline across all corpora, and, per corpus, full-text search, document reader, entity pages, network
  graph and timeline. `lib/globalindex.py` keeps the cross-corpus entity index it uses up to date.
* **`notebook/analysis.ipynb`**: Jupyter notebook over any corpus (centrality, communities,
  lead-finding, email networks, timelines, Gephi export) and across all of them (shared entities, collection
  overlap, an entity's documents per year in every collection). Generated by `notebook/make_notebook.py`.
* **`tests/smoke_test.py`**: an end-to-end test that builds two synthetic corpora covering every format and checks the index, every page and the cross-corpus views.
* **`data/`**: everything the pipeline produces (see [Data folder](#data-folder)); the source files stay where they are.

## Quick start

A `.venv` with everything below (except Homebrew's Tesseract) is already set up in the project folder. To recreate it:

```bash
python3 -m venv .venv
.venv/bin/pip install pymupdf flask networkx spacy markdown
.venv/bin/pip install xlrd extract-msg            # optional: legacy .xls and Outlook .msg
.venv/bin/python -m spacy download en_core_web_sm
brew install tesseract tesseract-lang              # OCR (+ non-English languages)

.venv/bin/python app/app.py                        # → http://127.0.0.1:5001
```

To keep the app running after the terminal closes: `nohup .venv/bin/python app/app.py >> data/app.log 2>&1 &`
(stop it with `pkill -f app/app.py`). It picks up newly built and rebuilt corpora on its own; restart it only
after changing its code.

Build (or rebuild) a corpus:

```bash
.venv/bin/python build/extract.py --corpus jfk     # text layer + OCR (cached; unchanged files are skipped)
.venv/bin/python build/index.py   --corpus jfk     # entities, graph, search index → data/jfk/index.db
```

Build every corpus in turn, quickest first, in the background (a queue that survives closing the terminal):

```bash
pgrep -fl pipeline.sh                              # already running? run only one queue at a time
nohup bash data/pipeline.sh > /dev/null 2>&1 &     # one line per step in data/pipeline.log
pkill -f "bash data/pipeline.sh"                   # stop the queue (then any extract.py / index.py it left running)
```

Each corpus is extracted, then indexed; a failed step skips that corpus's later steps and the queue moves on.
Rerunning is cheap: unchanged sources are skipped and OCR and NER results are reused. Edit the list in
`data/pipeline.sh` to change the order or add corpora, but only while the queue is stopped: bash reads the
script as it runs, so editing it mid-run can break the queue. Corpora that need language data that is not installed
(Russian OCR for `cbr`, the multilingual spaCy model for `conti-chats`) are skipped with a note in the log.

Download a corpus that has a `[fetch]` section (resumable; safe to stop and rerun):

```bash
nohup .venv/bin/python build/fetch.py --corpus cia-crest --log > /dev/null 2>&1 &   # detached; progress in data/cia-crest/fetch.log
.venv/bin/python build/fetch.py --corpus cia-crest --status
pkill -TERM -f "fetch.py --corpus cia-crest"                                        # stop gracefully
```

A connection that drops mid-file is resumed (HTTP Range) after a short pause for as long as each attempt
gets data, so archive.org's 100 GB files and the Wayback Machine's habit of cutting long transfers both work.
Files that still fail are left as `.part` and retried, from where they stopped, on the next run.

Trial runs on a slice: `--limit 200` (first 200 sources) or `--only 'emails/2016*'` on `extract.py`;
`limit = N` inside a `[[records]]` block reads only N rows. `python -m lib.packs` lists the knowledge
packs; `.venv/bin/python tests/smoke_test.py` checks the whole pipeline in about a minute.

### Adding a dataset that comes out next year

1. Put the files somewhere (any folder layout; zips, 7z and rar can stay packed).
2. `cp corpora/_template.toml corpora/<id>.toml`, then set `title`, `root` and `packs`, and decide on
   `archives` / `archive_members`, OCR language, date range and whether ALL-CAPS codename detection makes sense.
3. `build/extract.py --corpus <id> --limit 300`, `build/index.py --corpus <id>`, then look at the result
   in the app. Adjust the config, then run it on everything.
4. If the domain is new, write a pack (below). If the data is a table, use a `[[records]]` adapter.

## Knowledge packs

`lib/packs/<name>.py`. Every attribute is optional; see the docstring in `lib/packs/__init__.py`.

| Pack | Contents |
|---|---|
| `core` | ~200 countries and territories, major cities and U.S. states, international bodies, heads of state and government since 1945, militant and criminal groups, foreign intelligence services, major companies and news media; 20 cross-cutting themes (corruption, sanctions, nuclear, torture, disinformation …) |
| `markings` | Rules only, no entities: classification banners and portion markings stripped before matching, classification levels, court captions, "Declassify On − 25 years" date estimate. Required by `government` and `sigint` |
| `government` | U.S. agencies, committees and office-holders (DCI/CIA, FBI, AG, State, Defense, DNI, NSC); FOIA exemption codes and CREST stamps stripped; agency-of-origin rules from letterheads |
| `sigint` | The original Snowden gazetteer (484 entries), surveillance themes, codename stop-words, Five Eyes origin markings, SIDtoday "Run Date", news-org file-name dates |
| `diplomatic` | Cable header parser (SUBJECT → title, TAGS → topics and countries, `FM AMEMBASSY …` → origin, signer); routing lines stripped; consular, trade, aid and basing themes |
| `offshore` | Secrecy jurisdictions, corporate-service providers (Mossack Fonseca, Appleby, Alcogal …), private banks, leak figures; nominee, bearer-share, beneficial-ownership and trust themes |
| `military` | Services and commands, weapons systems, named operations; war-log themes (civilian casualties, IEDs, air strikes, escalation of force, medevac …) |
| `coldwar` | JFK/MLK figures, Warren Commission, HSCA, Church Committee, CIA covert programs (MONGOOSE, MKULTRA, COINTELPRO …); NARA record-form parser (record numbers → CIA/FBI/HSCA, two-digit "28 JAN 62" dates); release stamps stripped |
| `economic` | Central banks (with Russian aliases), regulators, banks, rating agencies, crypto; monetary, currency, capital-flight and banking-crisis themes with Russian-language patterns |
| `political` | Campaigns, parties, operatives, election and Russia investigations, influence operations, hack-and-leak personas; fundraising, polling, election-fraud-claims and January 6 themes |
| `epstein` | Epstein/Maxwell case properties, prosecutors, the 2008 non-prosecution agreement. Deliberately no list of "associates": appearing in these files implies nothing, and names come from the documents via NER |

Packs merge in the order listed. Entities with the same type and name combine (aliases unioned;
the later pack's description wins, so `sigint` keeps its Snowden-specific descriptions). An alias
already claimed by a more specific entity is not taken over by a later pack. `python -m lib.packs
--check core government sigint` lists aliases two entities both claim. Rules of thumb for new entries:
single-word aliases match case-sensitively, so leave out ordinary words ("Begin", "Total", "Orange")
and common first names. Themes are regexes, and a document needs `MIN_IDEA_HITS` (3) hits to be tagged.

## How it works

| Stage | What happens |
|---|---|
| **Discover** | Walks `root` with the config's include/exclude globs. PDFs, images, web pages, text, email (`.eml`, Apple Mail `.emlx`, `.mbox`, Outlook `.msg`), Word/PowerPoint/Excel, OpenDocument, RTF/`.doc` (macOS `textutil`), `.xls` (xlrd) and CSV become documents. Page scans matching `page_scan_pattern` are grouped. Archives: `.zip` members are read in memory; `.tar/.tgz` (standard library) and `.7z/.rar` (macOS `bsdtar`) are streamed once each. Only formats on `archive_members` are ever read. Executables, scripts and anything else are skipped and counted. |
| **Extract** | PyMuPDF text layer per page; pages with little text are rendered at 200 dpi and OCR'd with Tesseract (`ocr_lang`, cached in `data/<id>/ocr`). Office/ODF files are parsed as zip + XML (Word page breaks are kept). Web pages are read in the charset they declare; other legacy text uses `encoding_fallback`. Emails: headers → date, title, author, correspondents and *emailed* relations; attachments become extra pages (scanned attachments are OCR'd). Long texts are split into pseudo-pages. `[[records]]` adapters turn CSV rows, SQL-dump rows, chat logs (Jabber, Telegram, Discord, Slack; one document per conversation per day, with "messaged" links) or ICIJ nodes into documents. With `sidecar = "ia-hocr"`, the Internet Archive's per-page OCR saved next to a PDF replaces Tesseract. A manifest skips unchanged sources on reruns. |
| **Dedupe** | Identical files (SHA-1) fold into one document; the copies are listed on its page. |
| **Metadata** | Title, collection, publisher, date (headers → file name → pack hints such as Run Date, cable dates, NARA forms → *Declassify On − 25* → first date in the text; estimates are marked *est.*), classification and origin from pack rules plus config rules. Pack parsers read cable headers and NARA record forms. |
| **Entities** | ① Curated pack entities (alias matcher; on ALL-CAPS pages such as old cables, aliases also match in capitals). ② Auto-detected ALL-CAPS **codenames**: OCR misreadings of common words or known codenames (REFORT, SEGRET, JEWAVE) and all-caps surnames that NER finds in full names (Walter E. FAUNTROY) are set aside. ③ spaCy NER for people (and optionally organizations and places), kept if seen in ≥ 2 documents and cached per page in `ner_cache.db`; organization spans that are ordinary words ("State", "Senate") are dropped. ④ **Identifiers** by pattern: email addresses, IBANs (checksum-validated), phone numbers. ⑤ **Structured** entities from headers and records. ⑥ **Themes** by regex families. Classification banners, FOIA codes and cable routing lines are stripped first. |
| **Graph** | Co-occurrence within a page window (edge weight = shared documents, plus NPMI for distinctive pairs), and **typed relations** from structured data: sender → recipient, officer → company, entity → registered address. |
| **Search** | SQLite FTS5 (Porter stemming) over every page plus titles/file names/authors: `"phrase"`, `prefix*`, `OR`, `NOT`, `NEAR(a b, 10)`. |

The indexer streams documents through SQLite in three passes (dedupe → metadata + pages → entities), so
memory stays flat for hundreds of thousands of documents. NER dominates build time on big corpora
(about 90 pages/s on 6 cores), and it is cached, so re-indexing after a pack edit is fast.

## Using the app

* **Library** (`/`): every configured corpus with its size, date range and build status. The search box searches **all corpora** at once and shows where a name or phrase appears in each.
* **Per corpus** (`/c/<id>/…`): overview, search with facets (collection, origin, classification, document type, year), document reader with structured fields (email headers, cable TAGS, NARA form fields, registry data), entity pages, network and timeline. Old Snowden-only URLs (`/search`, `/doc/…`) redirect to `/c/snowden/…`.
* **Entity page**: description, aliases, documents by year, neighbourhood graph, co-occurrences and distinctive (NPMI) associations; **direct relations** from structured data; **also in** links to the same entity in other corpora.
* **Across all collections** (`/all/…`): entities, an entity page, network and timeline over every built corpus at once. An entity found in several corpora is matched by type and name, ignoring case, spacing and the accents of Latin letters; other scripts keep every letter (two different people with the same name are merged here; the corpus pages keep them apart). Document counts, co-occurrences and timeline values are summed over corpora, and NPMI is computed over all of them together. Spelling variants that fold together within one corpus count each document once; their co-occurrence links count the stronger variant's. The merged entity list lives in `data/global.db`; the app rebuilds it in the background whenever a corpus index is added, rebuilt or removed, and serves the previous version meanwhile, so newly indexed corpora appear without a restart. Links, mentions and documents are read from the corpus indexes.
* **Network**: switch links between *co-occurrence* and *direct relations* (corpora with email or registry data), toggle types, hide hubs and auto-detected entities, focus on an entity. Identifiers are drawn as hollow grey squares (a deliberate neutral, not a ninth colour).
* **Originals**: PDFs and images open inline. Web pages, emails and text are shown as plain text (scripts never run). Office files download. Archive members are read from the archive on demand. Records have no original file.

## Safety

Several folders hold live malware and exploit code (the Kaspersky/Equation zip, the Shadow Brokers and
EQGRP dumps, Hacking Team's source code). The pipeline never executes or unpacks anything to disk. Archive members are
read into memory only if their format is on the corpus's allow-list (`archive_members = ["pdf"]` for
the Snowden archive), and the app serves only indexed documents, never active content. PDFs are still
parsed by MuPDF, so treat the machine as you would any machine opening untrusted documents.

## Caveats

* **OCR noise.** 44% of Snowden pages came through OCR; the JFK files are almost all scans. Expect misspellings and occasional junk codenames or names.
* **Short names misfire on old documents.** The modern-world packs know "SEC", "ETA" or "AQ"; in 1960s cables those are a section number, an arrival time or OCR noise. The `coldwar` pack's `SUPPRESS_ALIASES` turns such names off in corpora that load nothing beyond `coldwar` and the packs it requires (jfk, rfk, mlk-2025); mixed-era corpora that also load `military`, `sigint` or `political` keep them. Full names still match, but an entity known only by a suppressed name (Sony, ZTE) is left out. A corpus adds names with `[index] suppress_aliases` and turns suppressed ones back on with `[index] keep_aliases`.
* **Auto-detected entities are unverified.** They are flagged *auto* and can be hidden. NER uses an English model by default; for other languages set `ner_model` (e.g. `xx_ent_wiki_sm`) and `ocr_lang`.
* **Dates are heuristics** unless they come from a header (email, cable, NARA form, registry). Estimates are labelled.
* **Co-occurrence is not a relationship**, and an email relation only means a message lists both addresses. Read the source pages.
* **Some 7z archives use compression filters libarchive can't read** (e.g. `wikileaks/afg-war-diary.html.7z`); unpack those with 7-Zip and point a corpus at the folder. Password-protected zip members are skipped.
* **SQLite on exFAT.** A new, empty file on an exFAT drive gets a temporary inode number that changes once the file has data, and SQLite then refuses to write to it ("attempt to write a readonly database"). The NER cache reconnects after creating its table, and the index and global builds run without a journal, which skips that check. Keep this in mind for any new SQLite file written to the drive.
* **Private individuals.** Several datasets here (email collections, bank customer data, membership lists) contain personal information about people who are not public figures, and some (e.g. the Hunter Biden emails) carry DDoSecrets warnings about tampering and provenance. Weigh that, and the source's own caveats, before republishing anything.

## Snowden index

Rebuilt with the generalized pipeline. A regression run with the original gazetteer alone reproduced
the old index exactly: 2,996 documents, 15,080 pages, 49,671 mentions and 23,152 edges identical. The
one intended difference: 4 documents with 1980s–90s dates in their file names now get those dates.
The current build adds the `core` and `government` packs: 1,543 entities (451 people, 409 programs and
codenames, 375 places, 81 companies, 77 agencies, 67 organizations, 47 themes, 36 technologies),
57,513 mentions and 32,405 co-occurrence links, up from 1,173 / 49,671 / 23,152. The previous index is kept
at `data/snowden/index-pre-generalization.db`; `FINDINGS.md` was written against it.
